# AmazingHand + SO-101

This hardware-specific integration replaces the stock SO-101 ID-6 gripper with
a Pollen Robotics AmazingHand on an independent serial bus. It is maintained on
the `hardware/amazinghand-so101` branch so upstream-compatible code remains
separate from lab hardware support.

## Module boundary

- LeRobot owns the SO-101 arm, cameras, policies, datasets, and CLI lifecycle.
- `submodules/amazinghand_wrapper` owns hand probing, calibration, safety,
  telemetry, torque state, and grasp-synergy mapping.
- `so101_amazing_follower` composes one arm and one hand.
- `bi_so101_amazing_follower` composes two independent arm/hand pairs.

There is deliberately no separate `so101_wrapper`: `SOFollower` is already the
canonical LeRobot SO-101 wrapper. The only common change is `use_gripper=False`,
which lets an arm run without probing the removed stock ID-6 motor.

## Install

```bash
git submodule update --init submodules/amazinghand_wrapper
python -m pip install -e submodules/amazinghand_wrapper
python -m pip install -e '.[feetech,core_scripts]'
```

## Read-only hand probe

Run this before any motor command:

```bash
amazinghand probe --port /dev/ttyUSB_HAND
```

Record the actual baudrate and model number reported by the exact hand. Stock
Pollen examples commonly use 1,000,000 baud, while an earlier LV snapshot used
250,000. Both are probed by default. Model numbers 1280 and 1284 are accepted by
default but should be narrowed after the first probe.

## Single-arm teleoperation

```bash
lerobot-teleoperate \
  --robot.type=so101_amazing_follower \
  --robot.id=so101_amazing_right \
  --robot.arm_config.port=/dev/ttyUSB_ARM \
  --robot.hand_config.port=/dev/ttyUSB_HAND \
  --teleop.type=so101_leader \
  --teleop.port=/dev/ttyUSB_LEADER \
  --teleop.id=so101_leader_right
```

The default action and observation state both contain six scalar values: five
arm joints plus `gripper.pos`. This keeps the usual SO-101 policy shape. Set
`--robot.hand_config.include_motor_observations=true` only for a new dataset
whose state schema intentionally includes all eight hand motor closures.

## Calibration and safety

Hand calibration is stored separately from arm calibration. It records explicit
fully-open and fully-closed raw endpoints with torque disabled. Connecting alone
never enables hand torque; activation requires complete calibration. Stale
commands, temperature/load threshold violations, communication errors, and
write failures all enter a fail-closed state and disable torque.

No command in this document is evidence of hardware validation. Before dataset
collection, record a read-only probe, a supervised low-speed smoke test, and a
bounded soak report for the exact hand and power supply.
